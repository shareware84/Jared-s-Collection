Edit the catalogue without rebuilding it

Change an item's category, sub-category, name or display order here, then export. You'll get an overrides.js file to upload next to index.html. Nothing here changes the original data, so deleting overrides.js puts everything back.

The photo is resized to 320px and stored with the item. New items appear in the table below and can be edited like any other. They are written to overrides.js; their pictures go into photos.js, so export both and upload them together.

Keep the photos.js beside this file current. Exporting photos.js writes out whatever this page has loaded — if the copy on disk is older than the one on the server, exporting will quietly throw away every photograph added since. Copy the live one down before a session.

Site metrics

The archive is a static file, so it cannot count its own visitors — something has to receive the hit. The public site carries a GoatCounter tag, which counts a pageview on load and an event each time an item record is opened. This page is deliberately not counted — it is a tool, not part of the site.

This page is kept off the server, so the dashboard opens in a new tab rather than inside a frame — GoatCounter only permits framing from a whitelisted domain, and a file on disk has none. The code is written into overrides.js on export, which is what makes the public site report to your account.
